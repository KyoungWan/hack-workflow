# 문서·보고서 작성

특정 파일을 만드는 기능이 아니라, 사용자가 요청한 문서를 실제 근거에 맞춰 간결하게 작성하는 기능이다.

## 1. 요청 형식 확인

- 사용자 요청과 과제 원문에서 문서 목적·독자·파일명·저장 위치·필수 항목·형식·분량을 확인한다. 이미 정해진 것은 다시 묻지 않는다.
- 사용자가 지정한 문서 종류·파일명·목차·형식을 우선한다. 과제 제출 형식과 충돌하면 차이를 알려 필요한 선택만 확인한다.
- 형식이 없으면 목적에 맞는 짧은 구성을 제안한다. 아래 기본안은 실행 안내 또는 AI 협업 회고를 요청했지만 형식이 없을 때만 제안한다. 그 외 문서는 해당 목적에 맞는 구성을 사용한다.
- 선택이 없어 작업이 불가능한 핵심 조건만 묻는다. 단순한 문서화 요청에 불필요한 확인 단계를 늘리지 않는다.
- 스킬 자체를 수정하는 요청에서는 프로젝트 문서를 만들지 않는다.

## 2. 근거 확인과 문체

- 코드·패키지 스크립트·설정·검증 결과·기존 문서·대화 기록 중 요청에 필요한 자료만 확인한다.
- 실제 기능·실행 명령·수치와 일치하게 쓴다. 오래된 화면·삭제된 정책을 현재 구현처럼 설명하지 않는다.
- 기본은 한글의 짧은 bullet point다. 항목당 한 가지 사실을 적고 긴 서론·결론·중복·불필요한 중첩을 피한다. 사용자가 문단·표·다른 언어나 형식을 지정하면 그 요청을 따른다.
- 문서에 필요한 범위만 쓰고, 기본적으로 항목당 1~4개 bullet을 목표로 한다. 지정된 필수 내용은 분량을 줄이려고 누락하지 않는다.
- 관측 사실·가정·확인 필요를 구분하고 검증하지 않은 내용을 통과로 쓰지 않는다. 비밀값·개인정보는 포함하지 않는다.
- 기존 문서는 관련 부분을 갱신하며 사용자 내용을 근거 없이 지우지 않는다. 문서화를 위해 업무 기능을 새로 구현하지 않는다.

## 3. 실행·운영 안내

- 사용자가 요구한 항목에 따라 기술 스택, 준비, 실행, 대표 시나리오, 테스트, 가정·제한을 정리한다. 필요 없는 항목을 자동으로 모두 추가하지 않는다.
- 대표 실행 경로 하나를 우선하고 여러 옵션을 길게 나열하지 않는다. 설정은 .env.example에 모으고 문서에는 준비 방법과 필수값만 안내한다. 기존 설정 파일은 불필요하게 덮어쓰지 않는다.
- 시나리오는 주요 역할의 시작 → 행동 → 결과로 요약한다. 테스트는 재현 명령과 확인 범위·실제 검증 상태를 연결한다.

## 4. 회고·AI 협업·개인 경험 답변

파일명과 관계없이 사용자 경험이나 판단을 서술하는 문서에는 아래 주제 확정 절차를 적용한다. 객관적인 실행 안내·테스트 결과 문서에는 이 절차를 강제하지 않는다.

### 주제 제안 → 사용자 확정

- 답변 본문을 먼저 작성하지 않는다. 실제 대화·변경·검증 기록을 읽고 요청된 각 질문에 맞는 후보를 2~3개 이내로 제안한다. 근거가 하나뿐이면 억지로 늘리지 않는다.
- 각 후보를 ‘사건 / 적합한 이유 / 확인된 근거’의 짧은 bullet로 제시한다. 사용자의 판단과 AI가 스스로 수정한 일을 구분한다.
- 대화형 입력 도구가 있으면 선택과 보완 의견을 받고, 없으면 짧게 묻고 기다린다. 사용자가 주제와 사례를 이미 확정했다면 다시 묻지 않는다.
- 근거가 부족하면 어떤 상황에서 무엇을 왜 바꿨는지 구체적으로 묻는다. 없는 갈등·담당자 답변·사용자 기여를 만들지 않는다.
- 확정 전에는 해당 경험 답변의 본문을 파일에 생성·덮어쓰거나 대화에 완성 초안으로 제시하지 않는다. 독립적인 실행 안내 작성은 계속할 수 있다.

### 확정 후 작성

- 실제 질문과 사용자가 확정한 주제에 답한다. 질문별 짧은 bullet 3~5개를 기본으로 하되 지정 분량을 우선한다.
- 사실 → 판단 이유 → 행동 → 확인 결과가 연결되도록 한다. 수치가 없으면 관찰 가능한 결과를 적고 성과를 과장하지 않는다.

## 5. 마무리

- 요청한 형식·필수 항목, 실제 코드·명령·수치, 주제 합의와 작성 내용을 대조한다.
- 생성·수정한 파일과 미확인 사항만 짧게 알린다. 제공된 과제 원문은 수정하지 않는다.
