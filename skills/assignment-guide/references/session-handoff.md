# 작업 인계·재개

세션 전환이나 컨텍스트 부족으로 작업을 이어가야 할 때 현재 상태를 짧게 기록하고, 재개 시 실제 상태와 대조한다. 제출 보고서나 대화 아카이브를 만드는 기능은 아니다.

## 인계 기록

- 기존 작업 기록을 갱신하고 같은 용도의 파일을 중복 생성하지 않는다. 사용자가 지정한 파일명·형식을 우선하며, 지정이나 기존 기록이 없으면 WORKLOG.md를 사용한다.
- 현재 목표와 고정 제약, 변경 파일·작업 상태, 마지막 관련 검증과 근거 위치, 미해결 결정, 다음 실행 하나를 남긴다. 검증 완료와 미완료를 구분하고 장황한 대화 이력은 넣지 않는다.
- 가능한 한 검사된 작업 경계에서 인계한다. 실행 중 명령·부분 수정·충돌이 있으면 현재 상태와 안전한 다음 행동을 명시한다. 인계 문서를 쓰기 위해 실행 중 프로세스를 중지하지 않는다.
- 병렬 작업이 있는 경우 디렉터리·브랜치·마지막 커밋·미커밋 변경·파일 담당·검사·통합 상태·의존성을 기록한다. 별도 세션이 별도 체크아웃을 뜻한다고 가정하지 않는다. 포트·DB·실행 프로세스 소유권도 필요한 경우 남긴다.
- 미커밋 파일이나 무시된 설정이 다른 체크아웃에 자동 전달된다고 가정하지 않는다. 비밀값과 불필요한 원문 로그는 제외한다.
- 기존 검증 기록의 위치와 상태를 인용한다. 인계만을 위해 구현 점검 전체를 다시 실행하지 않는다.

## 재개

- 사용자가 재개를 요청하면 기록과 실제 파일·프로세스·작업 상태를 비교한다. 필요하면 최소 관련 검사를 실행하고 오래된 근거를 표시한 뒤 승인된 작업을 이어간다.
- 인계 기록 작성 요청만으로 구현 작업을 자동 재개하지 않는다.

허용된 개발 인계에 사용하며 평가 규정이 금지하는 단계의 AI 사용을 허용하는 근거로 삼지 않는다.
