# CSV 탐색 UI

제공 CSV를 읽기 전용 웹 UI에서 선택·탐색하는 기능이다. 업무 구현과 데이터 품질 분석을 자동 시작하지 않는다.

## 구현 방식 선택

기본 구현은 Next.js다. **Next.js를 사용할 수 없는 환경에서만 [Python 템플릿](../assets/csv-viewer-python/)을 작업 폴더에 복사해 구현한다.** 사용자에게 확인된 환경 제약이나 런타임·의존성 설치 오류를 근거로 선택한다. 하얀 화면만으로 사용 불가라고 단정하지 않고 오류와 접속 설정을 확인한다.

Python 대안은 템플릿 폴더 전체를 새 작업 폴더에 복사하고 [동봉 안내](../assets/csv-viewer-python/README.md)를 따른다. 스킬 원본을 직접 수정하지 않는다. Python 3와 서버 포트 접근이 필요하며, 동봉된 브라우저 번들을 사용하므로 실행에 Node.js·npm·SQLite가 필요 없다. 아래의 동작·복사·필터·정렬·오류 표시 요구사항은 동일하게 유지한다. 실제 CSV 폴더를 지정하고 서버는 직접 실행하지 않으며 사용자에게 실행 명령과 접속 경로만 안내한다.

## Next.js 설치와 실행

- 기존 과제 웹앱과 별개로 CSV 탐색 전용의 기본 Next.js 앱을 새 폴더에 만든다. 기존 앱에 라우트를 추가하거나 기존 package.json을 수정하지 않는다.
- README와 파일 목록으로 실제 CSV 폴더를 확인한다. 원본 데이터는 수정하거나 앱의 public 폴더에 복사하지 않는다. 고정 데이터 경로를 가정하지 않고 대상이 불명확할 때만 사용자에게 묻는다.
- [동봉 코드](../assets/csv-explorer/)를 재사용한다. Next.js App Router, React, TypeScript, 브라우저용 csv-parse를 사용한다. 먼저 `node -v`와 정상 동작한 Next.js 앱의 package.json 및 설치 버전을 확인한다. SQLite와 Node.js 24 고정 조건은 없으며 Next.js 자체의 Node 요구사항은 충족해야 한다. 최신 버전을 임의로 선택하지 않는다.
- 아래 스크립트의 첫 인자는 새 앱 폴더, 둘째 인자는 실제 CSV 폴더, 셋째 인자는 정상 동작한 Next.js 앱 폴더다. 모든 경로는 명령 실행 위치 기준의 상대 경로 또는 절대 경로다. 기존 앱 폴더가 있으면 덮어쓰지 않고 중단한다.

```sh
node <스킬경로>/scripts/install-csv-explorer.mjs ./csv-viewer "<실제 CSV 폴더 경로>" "<정상 동작한 Next.js 앱 경로>"
```

서버는 사용자가 직접 실행한다. 생성이 끝나면 실제 앱 경로로 아래 명령을 안내한다.

```sh
cd "<생성한 앱 폴더>"
npm run dev
```

- 에이전트는 앱 생성·의존성 설치와 서버를 띄우지 않는 검사까지만 수행한다. `npm run dev`, `npm start`, `next dev`, `next start`를 직접 실행하거나 백그라운드·브라우저 테스트 도구로 서버를 자동 시작하지 않는다. 실행 폴더·명령·예상 접속 경로를 안내하고 서버 실행은 사용자에게 맡긴다.
- `/`는 `/data`로 이동한다. 화면은 `/data`, CSV 목록·원본 전달 API는 `/api/files`, `/api/file`로 같은 Next.js 서버에서 제공한다. 별도 Hono·Vite 서버와 4310 포트는 사용하지 않는다.
- 접속 주소는 Next.js가 출력한 주소의 `/data`다(기본 `http://localhost:3000/data`). 시험환경에서는 해당 Next.js 서버에 연결된 미리보기 주소에 `/data`를 붙인다. 필요한 포트는 `npm run dev -- --port <포트>`로 지정한다.
- 생성 도구는 참조 앱에서 next·react·react-dom의 정확한 버전을 가져와 고정한다. 버전을 확정할 수 없으면 중단한다. 생성 후 시험환경에서 확인된 실행 명령·포트·미리보기 연결 방식에 맞춘 명령을 사용자에게 안내하며, 프록시 경로나 basePath 등 별도 설정이 있으면 필요한 설정을 확인해 적용한다.
- 생성된 앱의 `config.json`에 CSV 경로를 저장하며 상대 경로는 새 앱 루트 기준이다. `CSV_DATA_DIR`로 재정의할 수 있고 절대 경로도 지원한다. 미설정·읽기 실패는 화면에 오류로 안내한다.
- 사용자가 운영 모드를 원하면 `npm run build` 후 사용자가 직접 `npm start`를 실행하도록 안내한다. 파일 시스템을 읽는 Node.js 서버가 필요하며 정적 HTML 내보내기로 배포하지 않는다.
- 이 앱은 인증 없는 개인용 데이터 탐색기다. 시험환경의 보호된 미리보기를 사용하고 민감한 데이터가 연결된 앱을 공개 배포하지 않는다.

## 동작과 경계

- 파일명 옆에 전체 행·열 수와 검색 결과 수를 한 줄로 배치한다. 표 최대화 버튼은 브라우저 전체화면 API 없이 앱 안에서 메뉴·검색·필터를 숨겨 표와 페이지 이동 영역을 넓힌다. 원래 화면 버튼 또는 Escape로 복귀하며 기존 검색·필터·정렬·접힌 메뉴 상태를 보존한다.

- 왼쪽 파일 메뉴는 작은 접기/펼치기 버튼으로 폭을 줄여 표 영역을 넓힐 수 있게 한다. 접힌 상태는 로컬 저장소가 허용되면 새로고침 후에도 유지한다. 접힌 메뉴의 내용은 키보드 탐색에서도 숨기고 버튼에 펼침 상태를 표시한다.
- 폴더의 CSV를 재귀적으로 찾고 파일 목록에서 선택한다. 업로드·파일 선택·저장 대화상자는 사용하지 않는다. 심볼릭 링크는 탐색하지 않으며 목록 밖 파일 경로를 API로 읽지 못하게 한다.
- 파일 크기, 선택된 파일의 전체 행·열 수, 검색 결과 수, 현재 페이지 범위를 구분한다. 헤더·행 번호 고정, 열별 색상, 열 너비 조절, 긴 셀은 표에서 말줄임 표시하고 빈 값은 구분한다. 셀 클릭 시 표시가 아닌 원본 전체 값(줄바꿈·빈 문자열 포함)을 즉시 클립보드에 복사한다. 행 번호 버튼을 클릭하면 헤더와 원본 행 번호를 포함한 행 전체를 탭 구분 형식으로 복사한다(헤더 레코드 + 데이터 레코드). 탭·줄바꿈·따옴표가 있는 필드는 인용 처리하고 빈 값·중복 헤더도 보존한다. 모달은 띄우지 않고 작은 메시지로 복사 성공·실패를 안내한다. 셀 값은 HTML로 해석하지 않는다.
- 전체 검색은 쉼표로 나눈 여러 검색어 중 하나라도 포함하면 표시한다(OR). 각 열 필터는 포함 또는 제외(NOT)를 선택한다. 포함은 쉼표로 나눈 값 중 하나라도 포함하는 행을 표시하고, 제외는 그 값 중 어느 것도 포함하지 않는 행만 표시한다(NOT (A OR B)). 빈 검색어만 입력한 조건은 적용하지 않으며 빈 셀은 비어 있지 않은 값의 제외 조건을 통과한다. 각 열 필터 내부의 쉼표도 OR로 처리하며 공백·빈 항목·중복 검색어는 정리한다. 서로 다른 필터 행과 전체 검색은 AND로 결합한다. 각 조건은 최대 50개 검색어, 전체 검색 조합은 2,000개로 제한한다. 전체 검색·여러 열별 포함 필터(AND, 최대 20개)·최대 3순위 문자/숫자 정렬·페이지 이동은 전체 데이터에 적용한다. 기본 화면에는 필터와 정렬 각 1행을 표시하고 작은 + 버튼으로 조건을 추가한다. 행별 × 버튼으로 삭제하며 정렬 순위는 화면의 위에서 아래 순서로 적용한다. 초기화·파일 전환 시 기본 1행으로 돌아간다. 원본 행 순서를 기본값으로 사용한다. 숫자 정렬은 사용자가 숫자 열을 선택했을 때만 사용한다.
- UTF-8 CSV, BOM, 따옴표 내부 쉼표·줄바꿈을 처리하며 중복 헤더도 위치 기준으로 보존한다. 다른 인코딩은 원본을 보존한 별도 UTF-8 변환본을 준비한다. 파싱 실패는 오류로 표시하며 값을 자동 보정하지 않는다.
- 시험 환경 호환성을 위해 Worker·별도 검색 프로세스는 사용하지 않는다. 검색·정렬·CSV 파싱은 브라우저에서 수행하므로 큰 파일은 브라우저 메모리를 많이 쓰거나 화면 응답을 지연시킬 수 있다. UI는 비동기 요청·로딩 안내·이전 요청 중단·페이지 단위 렌더링을 사용하고, 무중단을 보장한다고 안내하지 않는다. 실제 데이터 규모에서 조회 시간을 측정한다.
- 서버는 지정 폴더의 파일 목록과 선택한 CSV 원문만 전달한다. 브라우저는 선택 파일 전체를 읽어 파싱한 뒤 필터·정렬·페이지 이동을 수행하고 표는 페이지 단위로 렌더링한다. 같은 파일에서 검색·정렬할 때 재다운로드하지 않으며 파일을 다시 선택하면 원본을 다시 읽는다. 큰 파일을 무조건 처리할 수 있다고 안내하지 않고 실제 크기에서 메모리·응답성을 확인한다.
- 행 번호는 헤더를 제외한 CSV 레코드 번호이며, 따옴표 내부 줄바꿈을 포함하는 텍스트 줄 번호와 다르다.

## 실패 상태 표시

- 파일 목록 로딩 → CSV 파일 읽기 → CSV 해석 → 검색·정렬 → 표 표시 상태를 보여준다. 읽기·파싱 실패는 오류 영역에 표시한다.
- 클립보드 접근이 실패하면 원문을 선택 가능한 텍스트 영역에 표시하고 Ctrl/Cmd+C로 복사하도록 안내한다.

## 확인

1. Next.js 앱은 생성한 폴더에서 `npm run check`, `npm test`, `npm run build`를 실행한다. Python 대안은 복사한 폴더에서 `python3 -m unittest discover -s . -p 'test_*.py'`로 서버를 시작하지 않는 검사를 수행한다. 브라우저 소스를 수정한 경우 동봉 안내에 따라 테스트하고 번들도 다시 빌드한다.
2. 사용자에게 직접 서버를 실행하도록 안내하고, 실행 완료와 접속 주소를 전달받은 뒤 요청된 범위에서 작은 CSV로 전체 흐름을 확인한 후 실제 파일로 검증한다. 사용자가 실행한 서버에서 `/`의 `/data` 이동과 `/data` 화면·JavaScript 로딩, 두 조회 API를 확인한다. 시험환경의 실제 미리보기 주소에서도 점검한다.
3. 실제 CSV의 행·열·셀을 대조하고 필터(NOT 포함)·정렬·페이지 이동·셀 복사·헤더와 행 전체 복사·표 최대화가 동작하는지 확인한다. 파일 경로 제한과 파싱 오류도 확인한다.
4. 하얀 화면이면 터미널 오류, 브라우저 Console, Network의 문서·`/_next/` 자산·API 응답 순으로 확인한다. 로컬 성공만으로 시험환경에서도 검증됐다고 보고하지 않는다.
5. 공통 코드를 변경했다면 동봉 자산도 갱신하고 새 임시 앱에서 서버를 띄우지 않는 검사를 수행한다. 서버가 필요한 검증은 사용자 실행 후에만 수행하며, 실행되지 않은 항목은 미검증으로 남긴다. 앱 런타임에서 스킬 설치 경로를 참조하지 않는다.
