# CSV 탐색 UI

제공 CSV를 읽기 전용 웹 UI에서 선택·탐색하는 기능이다. 업무 구현과 데이터 품질 분석을 자동 시작하지 않는다.

## 설치와 실행

- README와 파일 목록으로 실제 제공 CSV 폴더를 먼저 찾는다. 원본을 수정하거나 LLM이 전체 CSV를 다시 작성하지 않는다. 데이터가 텍스트로만 제공되었다면 실제 CSV 경계·헤더를 확인해 별도 파일로 보존하고 복구·추정 여부를 알린다.
- [동봉 코드](../assets/csv-explorer/)를 재사용한다. 서버·UI를 매번 새로 생성하지 않는다. Node.js 24+, TypeScript, Hono, Vite, csv-parse를 사용한다. `src/core.ts`가 파일 조회·검색·정렬을 담당하고 UI·HTTP 어댑터와 분리되어 있다.
- 프로젝트 루트에서 아래 설치 스크립트를 실행한다. 경로는 현재 스킬의 실제 위치를 사용한다. 첫 인자는 프로젝트 경로, 둘째 인자는 확인한 실제 CSV 폴더이며 필수다. 프로젝트 루트 기준 상대 경로 또는 절대 경로를 사용할 수 있다. 고정 데이터 경로를 가정하지 않으며 후보가 여러 개라 대상이 불명확할 때만 사용자에게 확인한다.

```sh
node <스킬경로>/scripts/install-csv-explorer.mjs . "<확인한 CSV 폴더 경로>"
npm run csv
```

- 설치 도구는 `tmp-tools/csv-explorer`를 복사하고 해당 폴더에서 `npm ci`를 실행하며, 기존 package.json의 다른 설정을 보존하고 `csv` 스크립트를 추가한다. 기존 폴더나 csv 명령이 있으면 덮어쓰지 않고 확인한다.
- 실행 명령은 추가 인자 없는 **`npm run csv`**, 접속 주소는 **http://localhost:4310**이다. 127.0.0.1에만 바인딩한다. 포트 충돌 시 다른 포트로 몰래 전환하지 않고 기존 프로세스를 확인한다.
- `tmp-tools/csv-explorer/config.json`의 `dataDir`로 경로를 바꿀 수 있다. `CSV_DATA_DIR` 환경변수로도 재정의할 수 있다. 둘 다 상대 경로는 프로젝트 루트 기준이며 절대 경로도 지원한다. 경로가 미설정이면 실행을 중단하고 설정을 안내한다. 표준 실행은 프로젝트 루트의 npm 스크립트를 이용한다.
- UI와 API는 동일한 서버에서 제공한다. Vite는 실행 전에 UI를 빌드하고 별도 서버를 계속 띄우지 않는다. Next.js 등 과제 앱과 독립적으로 실행한다. 앱 통합은 요청받았을 때 수행하고, 기존 인증이 있는 앱 내부에 통합할 경우 해당 접근 정책을 따른다.

## 동작과 경계

- 파일명 옆에 전체 행·열 수와 검색 결과 수를 한 줄로 배치한다. 표 최대화 버튼은 브라우저 전체화면 API 없이 앱 안에서 메뉴·검색·필터를 숨겨 표와 페이지 이동 영역을 넓힌다. 원래 화면 버튼 또는 Escape로 복귀하며 기존 검색·필터·정렬·접힌 메뉴 상태를 보존한다.

- 왼쪽 파일 메뉴는 작은 접기/펼치기 버튼으로 폭을 줄여 표 영역을 넓힐 수 있게 한다. 접힌 상태는 로컬 저장소가 허용되면 새로고침 후에도 유지한다. 접힌 메뉴의 내용은 키보드 탐색에서도 숨기고 버튼에 펼침 상태를 표시한다.
- 폴더의 CSV를 재귀적으로 찾고 파일 목록에서 선택한다. 업로드·파일 선택·저장 대화상자는 사용하지 않는다. 심볼릭 링크는 탐색하지 않으며 목록 밖 파일 경로를 API로 읽지 못하게 한다.
- 파일 크기, 선택된 파일의 전체 행·열 수, 검색 결과 수, 현재 페이지 범위를 구분한다. 헤더·행 번호 고정, 열별 색상, 열 너비 조절, 긴 셀은 표에서 말줄임 표시하고 빈 값은 구분한다. 셀 클릭 시 표시가 아닌 원본 전체 값(줄바꿈·빈 문자열 포함)을 즉시 클립보드에 복사한다. 행 번호 버튼을 클릭하면 헤더와 원본 행 번호를 포함한 행 전체를 탭 구분 형식으로 복사한다(헤더 레코드 + 데이터 레코드). 탭·줄바꿈·따옴표가 있는 필드는 인용 처리하고 빈 값·중복 헤더도 보존한다. 모달은 띄우지 않고 작은 메시지로 복사 성공·실패를 안내한다. 셀 값은 HTML로 해석하지 않는다.
- 전체 검색은 쉼표로 나눈 여러 검색어 중 하나라도 포함하면 표시한다(OR). 각 열 필터는 포함 또는 제외(NOT)를 선택한다. 포함은 쉼표로 나눈 값 중 하나라도 포함하는 행을 표시하고, 제외는 그 값 중 어느 것도 포함하지 않는 행만 표시한다(NOT (A OR B)). 빈 검색어만 입력한 조건은 적용하지 않으며 빈 셀은 비어 있지 않은 값의 제외 조건을 통과한다. 각 열 필터 내부의 쉼표도 OR로 처리하며 공백·빈 항목·중복 검색어는 정리한다. 서로 다른 필터 행과 전체 검색은 AND로 결합한다. 각 조건은 최대 50개 검색어, 전체 SQL 검색 조합은 2,000개로 제한한다. 전체 검색·여러 열별 포함 필터(AND, 최대 20개)·최대 3순위 문자/숫자 정렬·페이지 이동은 전체 데이터에 적용한다. 기본 화면에는 필터와 정렬 각 1행을 표시하고 작은 + 버튼으로 조건을 추가한다. 행별 × 버튼으로 삭제하며 정렬 순위는 화면의 위에서 아래 순서로 적용한다. 초기화·파일 전환 시 기본 1행으로 돌아간다. 원본 행 순서를 기본값으로 사용한다. 숫자 정렬은 사용자가 숫자 열을 선택했을 때만 사용한다.
- UTF-8 CSV, BOM, 따옴표 내부 쉼표·줄바꿈을 처리하며 중복 헤더도 위치 기준으로 보존한다. 다른 인코딩은 원본을 보존한 별도 UTF-8 변환본을 준비한다. 파싱 실패는 오류로 표시하며 값을 자동 보정하지 않는다.
- 시험 환경 호환성을 위해 Worker·별도 검색 프로세스는 사용하지 않는다. 검색은 SQLite 동기 쿼리이므로 큰 데이터의 복잡한 검색 중 서버 응답이 지연될 수 있다. UI는 비동기 요청·로딩 안내·이전 요청 중단·페이지 단위 렌더링을 사용하고, 무중단을 보장한다고 안내하지 않는다. 실제 데이터 규모에서 조회 시간을 측정한다.
- 서버가 CSV를 스트림으로 읽어 SQLite 메모리 테이블로 캐시한다. 브라우저에는 페이지 단위로 전달한다. 파일 크기·수정시간 변경 시 다시 읽는다. 이 구현은 디스크보다 큰 규모를 위한 외부 메모리 엔진이 아니므로 데이터 규모가 서버 메모리를 넘으면 디스크 SQLite 방식으로 확장한다.
- 행 번호는 헤더를 제외한 CSV 레코드 번호이며, 따옴표 내부 줄바꿈을 포함하는 텍스트 줄 번호와 다르다.

## 확인

1. `npm --prefix tmp-tools/csv-explorer run check`와 `node --import ./tmp-tools/csv-explorer/node_modules/tsx/dist/loader.mjs --test tmp-tools/csv-explorer/src/*.test.ts`를 실행한다.
2. 실제 제공 CSV의 행·열·일부 셀을 대조하고, 가장 큰 파일의 검색·정렬·페이지 이동을 확인한다. 파싱 오류와 파일 경로 제한도 확인한다.
3. 브라우저에서 파일 전환, 열 색상, 검색, 필터, 페이지 이동, 셀 클릭 즉시 전체 값 복사·실패 안내를 확인하고 실행 명령·주소를 사용자에게 안내한다.
4. 공통 코드를 변경했다면 동봉 자산도 갱신하고, 새 임시 프로젝트에 설치 도구로 복사해 TypeScript 검사·특수 CSV 테스트·실행을 검증한다. 앱 런타임에서 스킬 설치 경로를 참조하지 않는다.
