# 후속 문제 생성

## 진행 방식

- “문제 만들어줘”처럼 번호 없이 요청하면 아래 15개 문항을 번호·순서·문구 그대로 모두 보여주고 선택할 번호를 묻는다. 목록을 먼저 제시하는 단계에서는 과제 자료를 추가로 읽거나 임의로 문제를 선택하지 않는다.
- 사용자가 번호를 선택하면 현재 과제 원문, 관련 구현·데이터 구조·검증 결과, 대화에서 확인된 가정·미구현 사항 중 해당 문항에 필요한 자료를 읽고 상황에 맞는 구체적인 문제를 만든다. 처음부터 번호를 지정했다면 목록을 반복하지 않고 바로 적용한다.
- 여러 번호를 선택하면 선택한 순서대로 번호마다 문제 하나를 만든다. 원래 번호를 유지하며 필요하면 한 문제 안에 관련 세부 질문을 둔다. 범위 밖 번호는 유효한 번호를 다시 선택하도록 안내한다.
- 실제 사용자 역할·화면·입력 필드·처리 단계·결과를 문제에 연결한다. 예를 들어 Happy Path 문항은 해당 시스템의 실제 시작 행동부터 결과 확인까지를 대상으로 묻는다.
- 장애·급격한 수치 변화 등 새 조건은 가상 상황임을 표시한다. 확인되지 않은 구현이나 대비책이 이미 존재한다고 전제하지 않는다. AI 활용 여부는 기록이 없으면 추정하지 않고 사용자가 구분해 설명하도록 묻는다.
- 현재 과제 맥락을 찾을 수 없으면 과제 설명이나 프로젝트 위치를 요청한다. 이 스킬 저장소 자체를 사용자의 과제로 임의 간주하지 않는다.
- 선택 후 출력은 선택 번호, 필요한 상황 설명, 질문으로 구성한다. 정답·해설·힌트·모범 답안은 요청받기 전에는 제공하지 않는다. 문제 생성만으로 코드 수정, 검증 실행, 보고서 작성, 답변 평가를 시작하지 않는다.

## 문항 목록

1. 구현한 부분 중 AI를 활용한 부분과 활용하지 않은 부분, 가정한 부분, 아직 구현하지 못한 부분을 각각 설명하시오.

2. 구현 과정에서 채택한 가정 하나가 실제 상황과 다르다고 밝혀졌다면, 어떤 결과가 잘못될 수 있으며 어디를 수정해야 하는지 설명하시오.

3. Happy Path에서의 사용자 시나리오와 그에 따른 데이터 흐름을 설명하시오.

4. 입력이 없거나, 값이 0·음수이거나, 허용 범위의 최솟값·최댓값일 때 어떻게 처리되나요? 해당 조건이 의미 없는 경우 그 이유를 설명하시오.

5. 데이터에 다양한 문제가 발생했을 때, 각 구현 단계에서 시나리오가 어떻게 진행되는지 설명하시오.

6. 서로 연결된 데이터의 값이 충돌하거나 참조 대상이 존재하지 않는다면 어떻게 판단하나요? 어떤 자료를 기준으로 삼으며, 판단할 수 없을 때 어떻게 처리하는지 설명하시오.

7. 구현된 시스템이 올바르게 작동하는지 확인하려면 어떤 검증 방법을 사용할 수 있나요?

8. 여러 처리 단계 중 일부가 성공한 뒤 다음 단계에서 실패하면 무엇이 남나요? 기존 결과의 보존과 재실행 방법을 설명하시오.

9. 특정 수치가 지나치게 변하면 어떤 일이 발생할 수 있나요? 이에 대한 대비책이 마련되어 있나요?

10. 동일한 입력으로 여러 번 실행하거나 같은 요청이 연속으로 들어오면 결과가 달라질 수 있나요? 중복 저장·계산·처리를 어떻게 다루는지 설명하시오.

11. 결과 생성 후 원본 데이터가 수정되면 기존 결과는 어떻게 되나요? 재계산 범위와 사용자에게 최신 결과임을 알리는 방법을 설명하시오.

12. 데이터나 사용자 수가 크게 증가하면 어느 단계가 먼저 느려질 것으로 예상하나요? 이를 확인할 측정 방법과 개선 방향을 설명하시오.

13. 핵심 업무 규칙이나 계산 기준 하나가 변경되면 어떤 파일·함수·데이터 구조에 영향을 주나요? 변경 후 다시 검증해야 할 항목을 설명하시오.

14. 비교할 정답이 없는 경우에도 결과의 타당성을 어떻게 확인할 수 있나요? 작은 수작업 사례, 불변조건, 독립적인 계산 등 적용 가능한 방법을 설명하시오.

15. 사용자가 “결과가 이상하다”고 신고했을 때 어떤 정보부터 확인하나요? 입력·처리 과정·출력을 연결해 원인을 좁히는 절차와 현재 부족한 기록을 설명하시오.
